# Защита Assignment 5

## Как объяснить проект за 40 секунд

«Я выбрал тему ночной обсерватории, потому что интересуюсь космосом и музыкой.
Здесь три независимые задачи. В первой храню состояние боя в объекте и меняю
его после допустимого хода. Во второй храню задачи в массиве объектов: сначала
меняю массив, затем вызываю renderBoard. В третьей проверяю форму через HTML
constraints и свои правила, обновляю превью при вводе и создаю финальную
карточку только после успешной проверки. В каждой задаче отдельный JS-файл».

Не учи это как заклинание. Открой код и найди каждую названную часть.

## Карта проекта

- `index.html`: семантическая разметка, поля, пустой контейнер доски, defer.
- `styles.css`: Grid, Flexbox, media queries, фокус, ошибки, победа и поражение.
- `task1-battle.js`: GAME → battleState → playTurn → renderBattle.
- `task2-board.js`: tasks → фильтр и сортировка → renderBoard → DOM.
- `task3-crew.js`: readCrew → getCrewError → validateCrewField → buildCrewCard.

## Task 1 — вопросы и короткие ответы

**Что такое state?** Текущие значения: HP, оставшиеся аптечки, раунд, фаза и лог.
HTML отображает state, но не является источником игрового состояния.

**Почему const GAME и let battleState?** GAME — конфигурация. Её объект
защищён Object.freeze. При рестарте battleState заменяется новым объектом,
поэтому нужна let. Обычный const запрещает переназначение переменной, но сам
по себе не запрещает менять свойства объекта.

**Как получить число от 8 до 15 включительно?**
`Math.floor(Math.random() * (15 - 8 + 1)) + 8`.
Math.random даёт число от 0 включительно до 1 не включительно. Умножение на 8
создаёт 8 равных интервалов; floor превращает их в 0…7; +8 сдвигает к 8…15.
Без +1 в длине диапазона максимальный урон 15 не выпадет.

**Зачем === вместо ==?** Строгое равенство сравнивает без приведения типов:
`3 === "3"` — false, а `3 == "3"` — true.

**Где && и ||?** Лечение запрещено, если `action === "heal"` И одновременно
`heals === 0` ИЛИ `heroHP === maxHP`. Скобки явно группируют вторую часть.

**Как сделать 10% критического удара?** `Math.random() < 0.10`.
Урон умножается на 2. В этом проекте критический удар возможен у обоих кораблей.

**Почему проверки стоят до round += 1?** Неверный ход не должен менять состояние
или расходовать случайные значения. Guard clause заканчивает функцию через return.

**Как работает защита?** На текущем ходу урон врага делится на 2 и округляется
вверх через Math.ceil. Если прилетело 5, после щита теряется 3. На следующем
ходу защита уже не действует, потому что проверяется текущее action.

**Почему после смертельного удара враг не атакует?** Условие enemyHP === 0
ставит фазу won, обновляет экран и выполняет return до контратаки.

**Почему HP не уходит ниже нуля и выше максимума?** Math.max(0, HP - damage)
снизу; Math.min(healAmount, maxHP - HP) ограничивает восстановление сверху.

**Как обрезается лог?** unshift добавляет новое действие в начало; slice(0, 5)
оставляет только пять последних записей.

## Task 2 — вопросы и короткие ответы

**Что содержится в массиве?** 12 объектов. id — уникальная строка, title и tag —
строки, priority и minutes — числа, outdoor — boolean, status — строка.

**Почему нельзя идентифицировать карточку индексом?** После фильтрации или
сортировки её позиция меняется. Уникальный id остаётся тем же.

**Что делает renderBoard?** Читает фильтр, считает общую статистику, выбирает и
сортирует видимые задачи, очищает контейнер и создаёт колонки и карточки.
После каждого изменения данных или фильтра функция вызывается снова.

**Что такое DOM?** Дерево объектов страницы, через которое JavaScript меняет
элементы, текст, атрибуты и классы.

**Почему createElement и textContent?** Мы явно создаём узлы. textContent
вставляет обычный текст, а не выполняет HTML. Например, строка `<script>`
останется текстом. replaceChildren удаляет старых детей перед новой отрисовкой.

**Что такое event delegation?** Один click-слушатель стоит на task-board.
Клик всплывает от кнопки к контейнеру. event.target.closest находит кнопку,
dataset.id сообщает нужную задачу, dataset.target — новую колонку. Новые кнопки
после render тоже работают без дополнительных слушателей.

**event.target и currentTarget?** target — исходный элемент клика, например
текст внутри кнопки; currentTarget — элемент с обработчиком, здесь контейнер.

**filter, find, map и sort?** filter возвращает подходящие элементы в новом
массиве; find — первый подходящий объект; map — новый массив преобразованных
значений; sort меняет порядок массива. Здесь сортируется результат filter,
поэтому исходный tasks не переставляется.

**Где собственный цикл?** getBoardStats проходит for…of по tasks. Считает done,
active и суммирует минуты незаконченных задач. Исходно: 2 done, 3 active, 145 минут.

**Почему Music может показывать пустую активную колонку и 3/3 сверху?** Фильтр
скрывает чужие категории. Лимит и статистика относятся ко всей доске, иначе
через фильтр можно было бы обойти ограничение.

**Почему aria-disabled, а не disabled на карточках?** Такая кнопка остаётся
доступна с клавиатуры и позволяет показать объяснение блокировки. Само
aria-disabled не блокирует JavaScript: реальная проверка есть в обработчике.

## Task 3 — вопросы и короткие ответы

**Какие четыре правила не выразить обычными HTML-атрибутами?** Уникальное имя
по массиву, сумма четырёх навыков ровно 20, минимум 7 у основного навыка роли,
цвет amber только для Engineer.

**Зачем noValidate = true?** Отключает всплывающие сообщения браузера при
отправке. Атрибуты required, min, max, step и pattern продолжают работать через
checkValidity и validity. Мы показываем свои понятные сообщения.

**Что делает preventDefault?** Не даёт форме перезагрузить страницу или
отправить стандартный запрос. Обработчик сам проверяет данные и строит карточку.

**input, change и blur?** input — изменение значения во время ввода;
change — подтверждённое изменение, например выбор option; blur — потеря фокуса.
Превью обновляется всегда, ошибки впервые появляются после blur.

**Зачем touchedFields?** Это Set из id уже посещённых полей. Пустая форма при
открытии не ругается. После отправки проверены все поля.

**Почему перепроверяются все touched поля, а не одно?** Правила связаны:
смена роли меняет допустимый цвет и минимальный навык; смена любого навыка
меняет общую сумму. Старые ошибки должны исчезать сразу после исправления.

**Зачем setCustomValidity("") перед проверкой?** Предыдущая пользовательская
ошибка иначе продолжит делать поле невалидным даже после правильного ввода.
Пустая строка снимает customError; затем проверяем заново.

**Почему valueAsNumber?** input.value — строка. `"4" + "5"` даст `"45"`.
valueAsNumber даёт число, а пустое/нечисловое значение — NaN. NaN не складываем
в превью, но само пустое поле всё равно будет отклонено required.

**Как считаются ошибки?** Счётчик считает невалидные поля, а не каждое правило
внутри поля. Первое найденное поле сохраняется в firstInvalid и получает focus.

**Как проверяется имя?** trim убирает пробелы по краям; toLowerCase нормализует
регистр; includes ищет имя в takenNames. После выдачи карточки имя добавляется
в массив, поэтому повторная выдача с тем же именем запрещена до перезагрузки.

**Зачем queueMicrotask после reset?** Событие reset приходит раньше, чем браузер
восстанавливает значения по умолчанию. Микрозадача обновляет превью уже после
завершения синхронного сброса.

   После render изменение только DOM исчезнет, потому что данные не менялись.
